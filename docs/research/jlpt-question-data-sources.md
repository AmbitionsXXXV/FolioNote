# JLPT 真题/题库数据源调研 — FolioNote `/jp-exam`（现为 `/japanese/practice/exam`）后端选型

> 调研日期 2026-07-06。三路并行调研(官方渠道、开源数据集、中文/商业生态)+ 关键结论当日 live 核实(jlpt.jp、GitHub/Gitee/HuggingFace API 直连)。与 `japanese-nlp-jlpt.md`(词表/汉字/语法点数据源)互补——本文只覆盖**考试题目本身**的数据源。

## 1. 结论(TL;DR)

**不存在合法可接入的 JLPT 真题数据源。** 真题版权归国际交流基金 + JEES 共同持有,官方无任何面向第三方的授权计划或 API;流通中的"真题库"(中文 App、GitHub 结构化数据集、Anki 牌组)全部溯源到盗版扫描件或考生回忆版,结构化不能洗白出处。

**推荐路线:自建"仿真题"内容管线**(与现有 30 道 mock 题的做法一致):

1. 素材层用已调研过的干净数据:JMdict/KANJIDIC2(CC BY-SA)+ Waller 系等级标签 + Tatoeba 例句(见 `japanese-nlp-jlpt.md` §4-5)。
2. 生成层:LLM 按现有四种题型(`kanjiReading`/`context`/`paraphrase`/`grammarForm`)批量出题 + 对抗校验(首批 30 题已用 10-agent Workflow 验证过此流程可行)。
3. 校准层:真题数据集(下文 §3)**仅作本地私有参考**,用于校准题型分布、难度、措辞风格——不入库、不分发。
4. 讲解层:红宝书/蓝宝书只借鉴**讲解格式**(现有 `JlptVocabularyGloss`/`JlptGrammarGloss` 类型即此结构),不碰其内容。

## 4. 中文/商业生态

- **供应链真相**:沪江、MOJi、芥末、烧饼、早道等 App 的"真题"= 官方图书扫描 + 考后**回忆版**(QQ群/网盘众筹重构,准确性无保证)+ 自家教师编写的**仿真题**;营销话术混用"真题"与"全真模拟题",后者才是它们真正可授权的部分。无证据表明任何一家持有 JEES 授权。
- **红宝书/蓝宝书**(华东理工大学出版社):是**原创教辅**(作者按考试趋势自编词表/语法讲解+练习),不是真题汇编;无开发者授权渠道;社区流传的 OCR 版属汇编作品侵权,出版社在该领域有维权记录。→ 只作讲解格式的风格参考。
- **日方出版社**(ASK 新完全マスター/総まとめ/TRY!、アルク等):全部走纸书/电子书/课程渠道,**无内容 API**;要拿正版内容只能逐家 BD 谈判,非独立开发可及。
- **越南系**(Migii/Mazii/Todaii):号称数万题,实为低成本自产仿真题 + 当地回忆版文化,同样无授权、不可作数据源。

## 5. 对 FolioNote 的落地建议

1. **短期(纯前端阶段延续)**:继续扩充自编题库——把首批 30 题的"LLM 出题 + 多 agent 对抗校验"流程固化为可重复的 Workflow,按级别×题型配额批量生产,产出直接写成 `JlptQuestion[]`。
2. **中期(接后端时)**:题目入库(新表,注意 [[db-lazy-stub-mirror]] 规则),配合 `japanese-nlp-jlpt.md` 计划中的 JMdict/等级词表种子数据,出题素材从种子表取(保证选项干扰项同级别、同词性)。
3. **校准(可选,本地私有)**:clone `jlpt-freq` 做词频/题型分布分析(它的 `analyze_freq.py` 现成),用统计结果指导生成配额与难度,**统计结果可用,原文不可入库**。
4. **UI 措辞**:界面上明确"仿真练习/exam-style practice",不自称"真题",与现有"级别为非官方参考"免责声明同框。
5. **如需真题体感**:购买官方公式問題集两册作编辑内部参考(人工对照风格),不数字化入库。

## 6. 调研方法备注

调研当日 Anthropic 侧 WebSearch/WebFetch 持续 529 过载,三路调研 agent 的初稿基于训练知识;本文所有关键事实(公式問題集册数、jlpt.jp 版权声明、各 repo 的 license/规模/数据样例、HF/Gitee 检索结果)已于 2026-07-06 通过 `curl` 直连逐项 live 核实。未 live 核实的判断(如中文 App 供应链、出版社无 API)为三路独立调研 + 既有研究文档交叉一致的训练知识结论,置信度高但无单一引文。
